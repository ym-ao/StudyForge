# V3.1 Batch 5 — Numerical MCQ and exact attempt review

## Implemented
- Added a deterministic numerical-template MCQ generator with one correct choice and configurable option count (2–6).
- Distractors use the same answer unit as the generated answer, are kept outside the template grading tolerance, and are retried with deterministic alternate seeds when formatted labels collide.
- Option order is deterministic for the attempt seed. Choice labels are checked after the configured decimal/significant-figure formatting so duplicate visible answers are rejected.
- Study and timed Exam now present generated MCQ choices for `VERIFIED` numerical templates. Existing numerical free-response remains the fallback when no MCQ choice set can be generated; non-verified templates and legacy numerical questions retain their prior behavior.
- Exam grading checks the generated correct option. The result view shows the exact generated answer, while the attempt snapshot now also records generated numerical option labels and correctness alongside the generated prompt, answer, seed and template version.
- Expanded numerical engine tests for deterministic choices, units, unique labels, one correct option, collision/failure, tolerance boundaries, constraints and formatting.

## Compatibility / persistence decision
- No Room migration or new in-progress Study attempt table was added. Batch 4's queue fingerprint + question ID already reconstructs the Study variant; adding persistence without a demonstrated resume inconsistency would be speculative.
- Existing exam snapshots are additive JSON fields; Room schema and backup schema are unchanged.
- Only `VERIFIED` templates use generated MCQ. Draft templates and legacy numerical questions keep existing behavior.
- No app version/versionCode, FSRS, signing, or user data changes.
