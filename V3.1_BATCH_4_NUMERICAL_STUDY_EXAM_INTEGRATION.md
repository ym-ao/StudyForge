# V3.1 Batch 4 — Numerical template Study/Exam integration

## Implemented
- Verified numerical templates now opt into generated variants in Study and timed Exam. Draft templates and Numerical questions without a template continue to use the original prompt, answer and exact-match grading path.
- Study loads the dedicated `numerical_template` content block and displays the generated prompt and substituted explanation. Numerical grading uses the generated answer with configured absolute/relative tolerance and supported unit conversion.
- Exam loads template blocks for its eligible numerical questions, displays generated prompts and applies the same tolerance/unit-aware grading.
- Added `NumericalTemplateAttemptRules` with deterministic FNV-1a seed derivation from an attempt key and question ID. Recomputing a variant for the same key/question reproduces the same values and answer after recomposition/process state restoration.
- Exam attempt snapshots now retain the generated prompt, expected answer, numerical seed and template version so completed attempts can be audited without regenerating a different answer.
- Added JUnit regression tests for deterministic reconstruction, question-level seed separation, tolerance grading and unit mismatch. Added a CI source-contract verifier.
- Legacy Numerical grading remains the fallback whenever there is no Verified template.

## Limits / not claimed
- Android Gradle/Compose compilation, full JUnit, Room instrumentation, emulator, APK build and physical-device testing have not run in this environment.
- Study seed reconstruction is derived from the stable queue fingerprint plus question ID; Exam seed reconstruction is derived from the saved start timestamp plus question ID. Completed Exam snapshots persist the exact seed, generated prompt, expected answer and template version. This batch does not add a persistent in-progress Study attempt table or a database migration.
- Numerical template authoring remains opt-in: only `VERIFIED` templates are dynamically used. Draft templates and legacy cards are not silently converted.
- No Room schema, JSON backup schema, app version/versionCode, FSRS, signing or user data changes.
