# V3.1 Batch 2 — Numerical template persistence and interchange

## Implemented

- Added `NumericalTemplateCodec`, a versioned JSON envelope (`formatVersion: 1`) with a 64 KiB payload ceiling, bounded prompt/explanation/formula/unit fields, bounded variable/constraint/equivalent-expression counts, and strict validation through the numerical engine on both encode and decode.
- Added dedicated `numerical_template` structured-content block storage. It does not overload `sourceTitle`, `sourceDetail`, `answer`, or other legacy question fields.
- Added repository save/load methods. Saving replaces the one dedicated block in-place or appends it after existing content blocks; duplicate template blocks are rejected rather than silently selected.
- Existing JSON backup export already snapshots all content blocks. Backup import now explicitly recognizes the dedicated kind and applies its tighter payload size bound. The outer backup remains schema 15; no Room migration is required.
- Existing question-version snapshots already include complete content blocks, so numerical template metadata participates in version history and restore without a new version-table schema.
- Existing CSV/Anki simple interchange is unchanged. Legacy Numerical exact-text grading remains untouched.
- Updated workflow artifact labels and their static integrity checks from V3.0 to V3.1 development artifacts; Android app versionName/versionCode remain unchanged until a real APK release is produced.

## Tests and verification

- Added codec tests for JSON round-trip, dedicated block attachment, unknown/oversized payload rejection, invalid formula rejection and missing-block failure.
- `verify_v31_template_persistence.py`: 9/9 source checks.
- `verify_v31_numerical_engine.py`: 11/11 source checks.
- All workflow Python checks are run separately and recorded in `BUILD_STATUS.md`.

## Boundaries / not yet implemented

- No editor authoring or preview UI in this batch.
- No Study or Exam integration: the new repository APIs and codec are ready for use, but the legacy Numerical grading path intentionally remains unchanged until end-to-end integration tests are added.
- The codec and JUnit tests have not yet been executed by Android Gradle in this environment. Backup behavior is supported by existing generic content-block serialization plus static checks, not a real Android restore test.
- No Room schema migration, JSON backup schema bump, app version bump, FSRS or signing changes.
